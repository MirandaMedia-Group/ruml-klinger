# Předání správci: preview a produkce

Push, merge a nasazení provádí uživatel. Následným pokynem pověřil agenta vytvořením PR a testy preview. Publikovat pouze větev `codex/ruml-klinger-frontend-optimization`, nikoli `main` s nedokončenou validací. Samotná publikace větve bez commitnutých úprav změny na GitHub nepřenese.

1. V Netlify otevřít **projekt ruml-klinger** a ověřit propojený repozitář `MirandaMedia-Group/ruml-klinger`, produkční větev, build `yarn build`, publish `dist`, Node 24, SSR preset `netlify`. Případnou base directory zachovat podle skutečného nastavení. Zkontrolovat, zda deploy preview spouští PR, nebo i push větve; před čekáním na preview zjistit skutečný spouštěč.
2. Porovnat env s `.env.example`: `NUXT_PUBLIC_API_BASE_URL`, `NUXT_PUBLIC_GRAPHQL_ENDPOINT`, `NUXT_PUBLIC_SITE_URL`, CF7 866/865, GTM-PVPZKVF, veřejný mapový klíč (případně historický `GOOGLE_MAPS_API`). CF7/GTM uživatel potvrdil, nepřepisovat podle jiného webu. Žádná tajemství nevkládat do veřejných proměnných. Mapový klíč nesdílet v konverzaci; potvrdit pouze správné doménové restrikce.
3. Ověřit `CONTEXT` preview/production a nepovolit omylem `NUXT_INDEXABLE=true` na preview. Canonical origin má zůstat `https://www.ruml-klinger.cz`, pokud správce výslovně nezvolí jinou politiku.
4. Po vlastní publikaci poslat **skutečnou adresu preview a identifikaci nasazené revize**. URL se neodhaduje. Z HTML odečíst nový Nuxt build ID a skutečný payload odkaz včetně query. Ověřit HTTP/status, cache hlavičky, cold/warm request ID a Durable hit na HTML i payloadu; lokální handler tuto distribuovanou cache nedokazuje.
5. Postupně projít skutečné kořenové kategorie a hlubší cestu, CS/EN produkty a partnery, výrobce, služby, hledání (včetně nenulového výsledku), obousměrné stránkování, historii/hash a jazykový přepínač. Nepřeložený produkt má přepnout do EN katalogu podle schválené volby. Pokud kariéra stále nemá živou nabídku Klingeru, neoznačovat produkční kariérní detail za otestovaný.
6. Na preview zopakovat měření funkčního menu se 3 vzorky na trasu, uvedeným DPR, CPU, sítí, consent a povolenými médii. Každou vlastní payload URL požadovat nejvýše jednou; hover/focus nesmí zahajovat prefetch. Projít všechna lazy média, ověřit skutečné CDN odpovědi, `currentSrc`, dekódování, fyzické rozlišení a výřez. Video i Google Maps vizuálně zkontrolovat. Při první neočekávané 5xx zastavit živou sadu a uchovat čas/URL/status/request ID/tělo; neopakovat bez uchování incidentu.
7. Formuláře neodesílat automatickým testem. Doručení, příjemce a skutečné chování GTM tagů vyžadují samostatnou vědomou kontrolu správce. GTM/GA při automatizovaných kontrolách zachytávat i v iframe a nových stránkách.
8. Teprve po kontrole preview správce provede merge/deploy. Následná produkční kontrola je samostatná sekvenční sada na novém build ID. Při opakovaných 503 či rozbitých médiích vyhodnotit návrat k poslednímu známému funkčnímu deployi; agent rollback bez pokynu neprovádí.

Není provedena změna WordPressu, serveru, DNS, webhooků ani Netlify UI. Není implementována migrace infrastruktury, automatický purge médií při změně CMS ani univerzální vyřešení cold cache/backendových timeoutů.
